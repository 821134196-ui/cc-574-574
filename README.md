# 企业合同原件借阅与归还核验系统

员工办理业务时申请借阅纸质合同原件，法务档案员登记交接，管理人员可随时查到
**每份合同现在由谁保管、实际经手人是谁、何时应归还**。系统对并发借阅、逾期续借、
密级/调岗变更、归还缺页四类关键风险做硬性拦截，交接与核验记录全程可顺序追查。

## 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Java 17 + Quarkus 3（REST Jackson / Hibernate ORM with Panache / Scheduler） |
| 数据库 | SQLite（WAL 模式，文件位于 `data/contracts.db`） |
| 前端 | Svelte 4 + Vite 5 |
| 扫描件存储 | 本地目录 `data/scans/` |
| 提醒 / 门禁 | 本地模拟（定时任务写库 + 控制台日志；门禁按角色放行并生成卡号） |

## 一条命令启动

```bash
./run.sh          # 构建前端，同时启动后端(8080)与前端(5173)
./run.sh dev      # 前端使用 Vite 热更新开发服务器
./run.sh test     # 运行后端拦截场景测试（7 个用例）
./run.sh build    # 仅构建后端 jar 与前端 dist
```

启动后访问 **http://localhost:5173** ，在登录下拉中选择演示身份即可。
首次启动自动建库、建索引并播种演示数据。

> 脚本会自动探测系统 Java/Maven，也支持用户态安装在 `~/tools/jdk-17*`、
> `~/tools/apache-maven-*` 的工具链。

## 业务流程

```
员工申请(填用途、到期日)
   └─> 管理员审批（复核密级；禁止自审；锁定密级与岗位版本）
          └─> 档案员从盒位取出原件 → 登记实际经手人 → 出库交接 + 模拟门禁
                 └─> 借阅中（到期前可申请续借；调岗/密级变更触发重核验）
                        └─> 档案员逐页核对正文/附件/盖章页
                               ├─ 核验通过且无未闭环异常 → 签为已还，原件归位
                               └─ 缺页/盖章缺失/损坏 → 异常处理（禁止签为已还）
                                                         └─> 管理员闭环 → 方可结案
```

借阅页面把**借阅人、实际经手人、到期日**放在同一张卡片上展示。

## 四类关键拦截（已被自动化测试覆盖）

1. **并发借阅** — 一份原件不能同时借给两人。
   数据库层用 SQLite 部分唯一索引 `ux_loan_active ON loan(contract_id) WHERE active=1` 兜底，
   申请流程再以进程锁串行化「检查在途→插入→提交」。8 个并发请求实测仅 1 单 200，其余 7 单 409。
2. **逾期续借** — 到期日早于今天时，续借申请直接 400；此前已提交的待审批续借，
   管理员审批时再次拦截（防止申请与审批之间跨过到期日）。定时任务对临期/逾期生成提醒并跟进。
3. **密级 / 调岗变更重核验** — 审批时锁定合同密级与借阅人岗位版本；之后合同改密级或
   员工调岗（`postVersion+1`）都会把在途借阅单标记为 `REQUIRED`，续借被 409 拦截，
   须管理员重新核验；核验时若现密级已不足，则继续拦截并提示收回原件，权限恢复且重验通过才放行。
4. **归还缺页** — 实到页数不足、登记缺页、附件缺失、盖章页不齐或描述损坏时，
   借阅单进入 `ANOMALY` 并生成异常单，**不能直接签为已还**；异常未闭环前即便再次逐页核验通过
   也不能结案；仅管理员可闭环异常并确认归还。

其他规则：用途必填；管理员不能批准/续批自己的申请；扫描件仅对**获授权岗位且密级匹配**者开放，
越权查看同样写入审计链。

## 顺序追查

- **交接链** `handover`：同一借阅单内 `seq` 从 1 递增，每条以 `prevId` 链接上一条，出库/归还按序追加。
- **全局审计链** `audit_log`：所有关键动作只追加、不修改删除，全局 `seq` + `prevId` 衔接，
  可从任一条向前回溯，断链即说明记录被破坏。前端「审计追溯」页提供完整链路视图。
- 归还核验、模拟门禁（方向/经手人/卡号/放行）均挂在借阅单下，可在借阅详情时间线查看。

## 主要接口（均带 `X-User-Id` 请求头标识操作人）

```
POST   /api/loans                         员工申请借阅
POST   /api/loans/{id}/approve            管理员审批（自审返回 403）
POST   /api/loans/{id}/issue              档案员出库 {handler:实际经手人}
POST   /api/loans/{id}/renewals           到期前申请续借
POST   /api/loans/renewals/{rid}/decision 管理员审批续借
POST   /api/loans/{id}/reverify           调岗/密级变更后重新核验权限
POST   /api/loans/{id}/return             归还逐页核验（缺页/损坏返回 409 并进入异常）
GET    /api/loans/anomalies?status=OPEN   待处理异常
POST   /api/loans/anomalies/{id}/resolve  管理员闭环异常
GET    /api/loans/custody/overview        每份合同当前保管人/经手人/应归还
GET    /api/loans/{id}/{handovers,checks,door-events,audit}
GET    /api/loans/audit/trail             全局顺序审计链
GET/POST /api/contracts…                  合同档案、密级变更、扫描件上传/授权下载
GET/PUT  /api/employees…                  员工与调岗/密级/扫描授权
GET    /api/reminders                     临期/逾期/跟进提醒（本地模拟）
```

## 说明与边界

- 演示环境用 `X-User-Id` 请求头模拟登录，生产应替换为统一身份认证（SSO/JWT）。
- 门禁、短信/邮件提醒均为本地模拟；真实部署替换 `DoorService`、`ReminderService` 即可。
- 申请串行锁为单实例方案；多实例部署时应改用数据库悲观锁/唯一约束重试或队列。
