# 企业合同原件借阅与归还核验系统

员工办理业务申请借阅纸质原件 → 管理人员审批 → 法务档案员从盒位取出原件、登记实际经手人并出库 →
到期前可续借、逾期自动提醒跟进 → 归还时逐页核对附件与盖章页，缺页/损坏进入异常处理、**不能直接签为已还**。

- 后端：Java 17 + Quarkus 3.17（REST / Hibernate ORM Panache / Scheduler），数据库 SQLite（社区方言）
- 前端：Svelte 4 + Vite，构建产物由 Quarkus 同进程静态托管
- 扫描件：保存在服务器**本地目录** `data/scans`，数据库只存文件名
- 提醒、门禁：**本地模拟**（写入站内通知表 / 通知铃铛），不接外部网关
- 一条命令启动，浏览器访问 <http://localhost:8080>

## 快速开始

## 业务规则与拦截点

1. **一份原件不能同时借给两人**
   - 数据库部分唯一索引 `ux_active_loan(contract_id) WHERE status IN (APPROVED,PICKED_UP,OVERDUE,REVOKED)` 兜底；
     审批时先查当前持有人，并发的第二笔审批拿到 `409 CONFLICT`（`并发冲突：该原件已被另一笔借阅抢先占用`）。
   - 待审批（PENDING）不占原件，可排队；批准即占位，拒绝/撤回自动释放。
2. **续借必须到期前申请**：借阅人在到期日当天及以后申请续借返回 400；审批落库时再次校验，防止审批期间逾期。
3. **逾期提示跟进**：定时任务每 60 秒扫描（也可在“借阅管理”页手动触发），到期自动转 `逾期未还`，
   向借阅人和所有管理员推送提醒；管理员可“催还跟进”。临期 2 天推送即将到期提醒。
4. **调岗 / 密级改变重新核验权限**：管理员执行员工调岗或合同密级调整后，该员工/该合同的在册借阅
   自动生成“权限重新核验”单：交接前拦截交接；判定不通过则借阅变为 `权限中止·催还中`（仍占原件，别人借不了），
   并向借阅人催还。系统二次校验真实密级，人工无法在仍不满足时强判通过。
5. **管理员不能批准自己的借阅**：申请与审批同人时返回 403，页面显示“禁止自批”，需其他管理员处理。
6. **归还缺页/损坏拦截签还**：档案员必须逐页提交全部页码（盖章页重点标注），任一页为缺页/损坏
   即生成异常单、借阅保持在册，返回 `blockedReturn=true`；异常全部由管理员闭环后，重新逐页核验、
   全部完好才能签为已还并回库、核销门禁。
7. **扫描件按岗位授权**：只有合同指定的“授权岗位”员工能查看/下载扫描件（按当前岗位判定），
   其他人看到 🔒 岗位未授权，接口直接 403。
8. **顺序追查**：申请、审批、交接、续借、逐页核验、异常、重检每一步都追加审计日志（自增序号即顺序，不可改），
   “借阅单链路”弹窗可按单回放全过程。

## 页面

- **合同台账**：盒位、密级、页数/盖章页、当前保管人、应还日期、逾期天数；员工申请借阅（填用途+天数）；
  档案员/管理员建档、上传扫描件、设置扫描件授权岗位。
- **借阅管理**：待审批、待审批续借、全部在借；**借阅人 · 经手档案员 · 到期日同一行**；
  档案员“登记交接出库”记录实际经手人并触发门禁放行（模拟）；员工续借；管理员催还。
- **归还核验**：逐页下拉（完好/缺页/损坏）+ 备注，盖章页醒目标记；历史各轮核验记录保留。
- **异常处理**：缺页/损坏单列表，管理员填写处理结论闭环。
- **权限管理**：调岗、密级调整、重检结论。
- **顺序审计**：全量操作时间线，可按借阅单/实体类型过滤。

## 目录结构

```
backend/   Quarkus 工程（domain/service/web 三层）
  src/main/resources/import.sql     建表后种子数据 + 互斥部分唯一索引
  src/main/resources/META-INF/resources/  前端构建产物（vite 直接输出到这里）
frontend/  Svelte 工程
data/      SQLite 数据库与扫描件本地目录（运行时生成）
test/      curl 端到端拦截验证脚本
run.sh     一条命令：构建前端 + 启动系统
```
